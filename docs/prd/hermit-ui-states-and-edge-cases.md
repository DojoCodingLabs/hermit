# Hermit: UI states and edge cases (W1 screens)

| Field | Value |
| :---- | :---- |
| Document type | UX states and edge-case specification, companion to `docs/prd/hermit-prd.md` |
| Source | PRD screen inventory (HM-*), the W1 stories and FRs, the cage contracts, the model runtime, notifications and the device-adaptive runtime |
| Purpose | Every W1 screen renders a defined state for missing, slow, denied, conflicting or broken data; no happy-path-only screen ships |
| Status | v1, W1 screens complete; later waves' screens are added when each wave is seeded |
| House rules | Stable IDs; no timelines; no em or en dashes; copy keys in es-419 and English; the cage and approvals are never bypassed by a state |

## How to read this document

Three layers: Part 1 is the finite set of states a screen can be in, Part 2 the rules every screen inherits, Parts 3 and 5 the per-screen coverage and the edge cases. Part 6 threads states into the Definition of Done; the appendix audits the current code.

| Convention | Meaning |

| `EC-<AREA>-NN` | An edge case with its UI resolution (Part 5) |
| `HM-*` | A screen ID from the PRD inventory |

## Part 1: canonical state taxonomy

| Code | State | Definition | Required anatomy |
| :---- | :---- | :---- | :---- |
| ST-LOAD | Loading | Initial data or the model is loading | A skeleton or the mascot's thinking pose in the final layout; nothing jumps on arrival |
| ST-LAZY | Incremental load | More content arrives into a rendered view (streamed tokens, older log entries) | Inline at the boundary; what is shown stays readable and scrollable |
| ST-IDEAL | Populated | Data present, normal case | The designed content |
| ST-EMPTY-FIRST | Empty, first run | Nothing exists yet because the user is new | The mascot, one line, and the action that creates the first item |
| ST-EMPTY-CLEARED | Empty, filtered or deleted | Data existed or a filter returns nothing | Names why it is empty; never implies Hermit is unused |
| ST-PARTIAL | Partial | Part of a turn or screen succeeded | Done parts render; the failed part says so with a retry |
| ST-STALE | Stale | A shown item no longer matches the world (dismissed notification, changed event) | A visible "out of date" marker; actions on it are disabled with the reason |
| ST-PENDING | In flight | A step runs or awaits the user (approval sheet open) | Status line with the step; the trigger disabled; no optimistic success for sends |
| ST-PROCESSING | Long-running | Model download, verification, a slow first turn | Determinate progress where known; elapsed seconds after 3 s; a stop where safe |
| ST-SUCCESS | Success | An action completed | The new state in words ("Guardado", "Recordatorio para las 21:00"); proportional, never louder than the action |
| ST-ERROR | Recoverable error | A step or fetch failed and can be retried | Cause in plain language, retry, the user's text preserved |
| ST-ERROR-FATAL | Fatal | The app or model cannot continue | Error boundary with a route back (restart model, reinstall model); never a blank screen |
| ST-OFFLINE | No network | Expected for everything local; matters only for sending | No warning for local actions; sends say they need the network |
| ST-FORBIDDEN | Permission missing | The OS permission a skill needs is not granted | What is missing, why, and the one button that opens the right settings page |
| ST-BLOCKED | Blocked by the cage | The policy refused the action | Coral, the rule's reason in words, nothing done, no bypass |
| ST-TAINTED | Tainted session | The turn read content written by others | A visible marker; any send shows the taint warning on its sheet |
| ST-EXPIRED | Expired | An approval waited too long | What expired; the request can be made again from the chat |
| ST-DEGRADED | Degraded | Heat, low battery or a slow phone limit the model | A quiet line naming the limit ("Respuestas más cortas mientras el teléfono se enfría") |
| ST-UNSUPPORTED | Below the floor | The phone cannot run the model usefully (PDR-025) | The reason, forms that still work, and the opt-in with its warning |
| ST-DISABLED | Disabled control | A control's preconditions are unmet | Visibly disabled with the reason discoverable |

State anatomy rules:
- Thinking is honest. The status line names the real step (intent, skill, writing); elapsed seconds appear after 3 s; reasoning is behind the closed "Pensando" panel.
- Sends are never optimistic. A reply shows as sent only after the platform confirms.
- The two empties differ: first-run invites the first action; cleared explains why.
- Errors carry cause, recovery and the preserved text. The honesty guard means a failed action never reads as done.
- Every state honors reduced motion: the mascot pose changes without animation and the pulse is replaced by a static label.

## Part 2: cross-cutting state rules

**Model lifecycle.** The model has its own states, shown on HM-CHAT-02 and reflected in HM-CHAT-01's mascot: not downloaded (redirect to HM-ONB-03), downloading, verifying, verification failed, loading (first turn after launch), ready, throttled (ST-DEGRADED), unloaded under memory pressure (reloads on the next turn with ST-LOAD). The chat input stays usable in every state; a turn sent before the model is ready waits with ST-PROCESSING.

**Turn lifecycle.** Each turn moves through: sent, intent known (instant from the router), step running, approval pending, executed or blocked, writing, finished. Each has a status line copy key (`HM-CHAT-01.doing.*`, `HM-CHAT-01.writing`). Ending states: final answer, question (`needs_user`), or an outcome (`common.outcome.*`). Q155: a final answer that used up its tokens ends **cut**, never shown as finished (the engine's stop reason, `EngineResult.stop`); one the user stopped while words were on screen ends **stopped** and keeps them. Both say so under the bubble and offer Seguir, which runs only on the user's tap, words only.

**Offline is normal.** Remember, recall, reminders, calendar and reading captured messages work offline with no indicator. Only sending a reply needs the network; the sheet says so before the fingerprint, and a failure after approval says "not sent" plainly.

**Permissions.** Notification access (the WhatsApp listener) and calendar access are separate. A missing permission is ST-FORBIDDEN at the point of use, with the restricted-settings help on Android when the toggle is greyed out. Denial is never repeated as a nag; HM-ONB-04's "Not now" holds until the user asks for that skill.

**The cage and approvals.** Blocked actions are coral with the rule's reason. The approval sheet always shows the exact action, recipient and text, and the taint warning when the session read others' content. A sheet left open expires (ST-EXPIRED). Nothing a model wrote stays beside an open sheet.

**Untrusted content.** Messages and event text written by others render as quotes, never as Hermit's words, and the session shows ST-TAINTED until it ends.

**Heat, battery and slow phones.** The device-adaptive runtime shrinks thinking first, then reply length. The chat shows ST-DEGRADED once per session, not per turn. Below the floor is ST-UNSUPPORTED (PDR-025).

**Copy and accessibility.** Every state's copy has an es-419 and an English key. State changes are announced through `accessibilityLiveRegion` (the status line, the mascot label); buttons have roles and the expanded state for the "Pensando" panel.

**TalkBack, large text and dark mode (SL-27, NFR-08).** Every Pressable, Switch and TextInput has a role and a label from copy (checked by `apps/mobile/src/a11y-scan.test.ts`); a sheet body that only swallows taps is hidden from TalkBack. A streaming reply is never a live region: the finished reply, question or outcome is announced once, whole (`turnAnnouncement` in `packages/runtime/src/chat-state.ts`); the seconds counter and the live reasoning are not live regions either. Text follows the phone's font scale with no fixed heights on text containers; every screen and sheet scrolls, so layouts hold to 200% without clipping. Dark mode is Deep sea, light is Quiet craft; both pass WCAG 2.2 AA for the text and control pairs the screens use (the same test). The mascot uses the rig's dark renders in dark mode and is never recolored.

## Part 6: states in the Definition of Done

- Each W1 slice issue lists the `ST-*` states its screens render and the `EC-*` it resolves.
- A slice is done when every listed state renders with copy in both locales, is reachable in a test or the journey script, and honors reduced motion.
- New states or edge cases are added to this document in the same PR, with new IDs; IDs are never reused.
- `python3 scripts/prd_lint.py states docs/prd/hermit-ui-states-and-edge-cases.md --prd docs/prd/hermit-prd.md` stays clean.
