# Hermit: how open-source projects "connect to everything" (source-level read)

Date: 2026-11-11. Scope: read the source of seven projects to check and sharpen EP-25, ADR-017, CT-12 and FR-CONN-01..08. Complements `docs/research/connectors.md` (platform level) without repeating it. **V** = verified in the file or URL given; **U** = unverified. Files read through the GitHub API and raw URLs on their default branch on 2026-11-11; no clones.

## Comparison

| Project (license) | How an integration is declared | Auth model | Risk / permission metadata | Generated on the fly? | Reusable by Hermit |
|---|---|---|---|---|---|
| Nango (Elastic 2.0, repo wide) | One YAML entry per provider (data) plus TypeScript "functions" (code) | 1,241 providers; `auth_mode` enum (OAUTH2, API_KEY, BASIC, MCP_OAUTH2, ...); PKCE on by default, `disable_pkce` per provider | None per action | No | Pattern and schema only; data blocked by license |
| Activepieces (MIT outside `packages/ee`) | TypeScript `createAction` (code) | `PieceAuth.OAuth2` with `pkce`, `pkceMethod`, `grantType` | `classification`: READ, SEARCH, WRITE, DESTRUCTIVE; `aiMetadata.idempotent`; `audience` | Dev-time only (agent skill writes code) | Classification enum, AI description rules |
| n8n (Sustainable Use License, fair code) | "Declarative" node: JSON-like `routing` per operation, but with `preSend` code hooks | Credential types; generic OAuth2 credential has a `pkce` grant type | `usableAsTool` flag only | No | Lesson: declarative leaks into code |
| MCP spec + Registry (Apache 2.0 / MIT) | `server.json` (data) | Registry lists remotes and secret headers; auth itself is MCP authorization | `ToolAnnotations`: readOnly, destructive, idempotent, openWorld hints, explicitly untrusted | n/a | Registry API, annotation names |
| Goose (Apache 2.0) | Extensions are MCP servers (stdio, Streamable HTTP, builtin) | `env_keys`, OAuth for HTTP extensions | AlwaysAllow / AskBefore / NeverAllow; SmartApprove asks an LLM if a call is read-only | No | `available_tools` allowlist, OSV malware check |
| openapi-mcp-generator (MIT) | Generates a server (code) from OpenAPI 3 | Reads `securitySchemes` | HTTP method mapped to MCP annotations, `x-mcp-annotations` override | Deterministic, no LLM | Mapping table and SSRF guard |
| Pipedream components (Source Available, no competing service) | JavaScript module per action (code) | App file per service, hosted OAuth | MCP `annotations` on every action | No | Confirms annotations as the common vocabulary |
| Arcade MCP SDK (MIT) | Python `@tool` decorator (code) | `requires_auth=OAuth2(id, scopes)` per tool; `requires_secrets` | `Behavior` (operations: read, create, update, delete, opaque) plus `ServiceDomain` (email, payments, ...) with validation rules | No | Per-operation scopes, operations enum, validation rules |

## Findings per project

**Nango.** `packages/providers/providers.yaml` (V, 1.2 MB, 1,241 top-level entries, published as npm `@nangohq/providers` 0.72.4) is the best OAuth endpoint registry in open source. An entry carries `authorization_url`, `token_url`, `authorization_params` (Google: `access_type: offline`, `prompt: consent`), `scope_separator`, `authorization_method`, `proxy.base_url`, `retry` and `paginate` hints. Counts (V, grep of the file): API_KEY 492, OAUTH2 317, BASIC 120, OAUTH2_CC 113, MCP_OAUTH2 40; `disable_pkce: true` on 77 entries, so PKCE is the default. Of the MCP_OAUTH2 entries, 36 use `client_registration: dynamic` with a `registration_url` (Notion, Linear, Asana, HubSpot, Sentry, Vercel, Airtable, Canva...), meaning no client secret is needed; `slack-mcp` is `static`. **License blocker**: the repo `LICENSE` is Elastic 2.0 (V, https://github.com/NangoHQ/nango/blob/master/LICENSE), `LICENSE_SHORT` says "all rights reserved", the providers package has no own license field (V, npm registry). Hermit is Apache 2.0 (PDR-005); vendoring the file would put non-OSI terms in the repo. Endpoint URLs are facts, but the compilation is Nango's. Use it as a lookup to know which fields matter and where to look, and source each shipped endpoint from the provider's own docs.

**Activepieces.** Actions are code (`packages/pieces/framework/src/lib/action/action.ts`, V). The interesting part is metadata in `piece-metadata.ts` (V): `ActionClassification = READ | SEARCH | WRITE | DESTRUCTIVE`, `isReadOnlyClassification`, `AiMetadata {description, idempotent}`, `Audience human | ai | both`. Their authoring rules (`.agents/skills/piece-builder/ai-metadata.md`, V) say every new action must ship all three, the AI description must state side effects ("retries duplicate"), and the raw `custom_api_call` escape hatch is `audience: 'human'`, never an agent tool. OAuth2 props carry `pkce` and `pkceMethod: plain | S256` (`property/authentication/oauth2-prop.ts`, V). AI generation exists only as a developer-side agent skill (`.agents/skills/piece-builder/SKILL.md`, V: research API docs, scaffold, implement) that writes TypeScript reviewed by humans; nothing is generated at runtime. Their MCP server exposes piece actions with semantic tool search (`brain/knowledge/ai-intelligence/mcp-server.md`, V).

**n8n.** The "declarative" style (V, `packages/nodes-base/nodes/Brevo/Brevo.node.ts`: `requestDefaults.baseURL`, `ContactDescription.ts`: `routing.request {method, url}`) is close to CT-12, but Brevo alone has 23 `preSend` function hooks across two files (V). Real APIs need request shaping, and the escape is code. Any node becomes an agent tool by `convertNodeToAiTool` (`packages/cli/src/tool-generation/ai-tools.ts`, V) with no risk field. Generic OAuth2 credential offers `authorizationCode`, `pkce`, `clientCredentials` (`credentials/OAuth2Api.credentials.ts`, V). License is fair code, not OSI: pattern only.

**MCP spec and Registry.** `ToolAnnotations` (V, `schema/2026-07-28/schema.ts` in modelcontextprotocol/modelcontextprotocol) says: "Clients should never make tool use decisions based on ToolAnnotations received from untrusted servers." Defaults: `readOnlyHint false`, `destructiveHint true`, `openWorldHint true`. Registry `server.json` (V, `docs/reference/server-json/draft/server.schema.json` in modelcontextprotocol/registry) lists `remotes[]` of type `streamable-http` with `headers[]` whose inputs carry `isSecret`; it does **not** list tools or OAuth metadata. Live API works: `GET https://registry.modelcontextprotocol.io/v0/servers?search=...` (V), entries tagged `_meta.io.modelcontextprotocol.registry/official.status`. Many results are third-party proxies (e.g. Smithery-hosted remotes that require a Smithery bearer token, V in the same response), which route the user's data through someone else's server.

**Goose.** Extensions are MCP servers; config has `available_tools` (a per-extension allowlist) and `env_keys` (V, `crates/goose/src/agents/extension.rs`). Permissions: `AlwaysAllow | AskBefore | NeverAllow` (V, `crates/goose/src/config/permission.rs`). "SmartApprove" auto-allows tools with `readOnlyHint` and otherwise asks an LLM judge to classify read-only calls (V, `permission/permission_inspector.rs`, `permission_judge.rs`). It also runs an egress inspector on shell/web calls (`security/egress_inspector.rs`, V) and an OSV malware check before launching stdio packages (`agents/extension_malware_check.rs`, V). Hermit should copy the allowlist and refuse the LLM judge: letting a model downgrade risk contradicts FR-CONN-04.

**openapi-mcp-generator.** Emits a Node server (code), so its output is unusable for Hermit, but `src/parser/extract-tools.ts` (V) has a clean deterministic mapping: GET, HEAD, OPTIONS, TRACE to read only; PUT and DELETE to destructive and idempotent; PATCH to destructive; POST and unknown to non-destructive write; `x-mcp-annotations` overrides; `x-mcp-title` for names; tool name shortening. `src/utils/parser-security.ts` (V) blocks external `$ref` by default as an SSRF guard and rejects Swagger 2.0.

**Pipedream.** Code under a Source Available license barring competing services (V, repo `LICENSE`). Every action carries MCP `annotations` (V, `components/slack_v2/actions/archive-channel/archive-channel.mjs`).

**Arcade.** `arcade_core/auth.py` (V) declares auth and scopes per tool (`requires_auth=Google(scopes=[...])`). `arcade_core/metadata.py` (V) adds `Behavior {operations[], read_only, destructive, idempotent, open_world}`, an `Operation` enum (read, create, update, delete, opaque), a `ServiceDomain` enum (email, payments, messaging, calendar...), and validation rejecting contradictions (mutating plus read_only, delete without destructive).

## Cross-cutting conclusions

1. Nobody ships purely declarative connectors at scale; n8n's still need code hooks. "Spec, never code" holds only with a fixed set of declarative transforms in the runtime; MCP fills the remaining gap.
2. Nobody generates integrations with an LLM at runtime (Activepieces uses coding agents at authoring time, with human review). Hermit's phone-drafted spec (Q25) has no prior art, so its rails matter more.
3. Risk metadata converged on MCP's four hints, always treated as hints. PKCE is the default wherever modeled, and MCP dynamic client registration removes the client secret for many popular services.

## What Hermit should take

1. **OAuth provider table: build Hermit's own, do not vendor Nango.** Ship Hermit's own `oauth-providers.json` (Apache 2.0) using Nango's field set as the template: `authorization_url`, `token_url`, `authorization_params`, `scope_separator`, `pkce` (default true), `token_auth_method`, `base_url`, `registration_url`. Source each value from provider docs. Note in ADR-017: Nango `providers.yaml` is Elastic 2.0, reference only (V).
2. **Prefer MCP with dynamic client registration over a relay.** For Notion, Linear, Asana, HubSpot, Sentry, Airtable (Nango marks them `dynamic`, V; confirm each), the phone can register itself and run PKCE with no secret. Update FR-CONN-06 order or Q24 notes: a DCR-capable official MCP server beats a spec that needs the relay.
3. **Extend CT-12 operations with effect metadata**, aligned to MCP names so imports map one to one: `effect: read | search | create | update | delete | opaque`, `destructive`, `idempotent`, plus connector-level `domain` (Arcade-style: email, payments, messaging, calendar...). Keep Hermit's own `risk` as the cage input and derive a floor from effect and domain (e.g. `domain: payments` and not read gives at least spend; `email` plus create gives send). Add Arcade's contradiction checks to spec validation.
4. **Add `scopes[]` per operation** (Arcade pattern), so a connector requests only the scopes of the operations the user enabled, and the approval sheet can show them.
5. **Confirm FR-CONN-05 and harden it.** The MCP spec itself says annotations from untrusted servers must not drive decisions (V). Rule: only `readOnlyHint: true` from a server the user installed can *propose* read; anything else is `remote_write` or higher; `destructiveHint` absent means destructive (spec default). Never adopt Goose SmartApprove (LLM judge lowering risk).
6. **Per-connector tool allowlist** (Goose `available_tools`): on install the user sees all operations and tools; disabled ones never reach the model. Fits "the user picks which operations" in FR-CONN-06.
7. **OpenAPI import: port the method mapping, not the generator.** Reimplement `getToolAnnotations` (MIT, attribute it) with Hermit floors: GET and HEAD are read; POST with an obvious search shape stays write until the user raises trust; honor `x-mcp-annotations` only upward. Block external `$ref` and reject Swagger 2.0 as they do.
8. **Registry filter.** When discovering from the MCP Registry, prefer `official` active entries whose remote host matches the service's own domain; flag third-party proxy remotes (Smithery and similar) as "your data passes through X" in the install sheet.
9. **No raw HTTP tool for the model** (Activepieces keeps `custom_api_call` human-only). A drafted spec must list concrete operations; no "call any path on this host" operation.
10. **Bounded transform vocabulary in the runtime** (lesson from n8n `preSend`): define it now in CT-12 (`bodyTemplate`, `query`, `headers`, `pagination: cursor | offset | link`, `resultPath`), so drafted specs have somewhere to put shaping logic other than code.
11. **AI description field with side effects** (Activepieces rule): CT-12 `aiDescription` must state what the call changes and whether a retry duplicates; drafted specs get it from the model but it is shown to the user before approval.

Unverified items to check before building: whether each "dynamic" Nango MCP provider accepts public clients with PKCE and custom app-link redirects (U); Google's and Slack's policy on mobile app-link redirects for their own MCP servers (U).
