# Tether QVAC deep-dive (for Hermit)

Research date: 2026-11-08. Source of truth: shallow clone of `github.com/tetherto/qvac` at commit `a05a916` (HEAD of default branch, 2026-11-09 UTC push), `npm view`, `gh`. Clone path: `(local clone) qvac/` (all paths below are relative to that unless they start with `http`). Code was read only; nothing from the repo was installed or executed.

---

## 1. Summary

- **Version and license.** `@qvac/sdk` latest is **0.23.0** (npm publish 2026-11-02; changelog date 2026-10-29). License **Apache-2.0** for the monorepo and SDK. It is still 0.x. There have been 51 releases since 0.1.0 on 2025-10-17, and a minor release lands about every 2 weeks. **Every recent minor has breaking changes**: 0.19 had 8 sections in `breaking.md`, 0.20 had 5, 0.21 had 3, 0.22 had 9 and 0.23 had 10. The project is very active (754 stars, 73 contributors, a weekly CI run on physical-device farms), but the API is not stable.
- **Architecture.** The SDK is a thin TypeScript client. All inference runs in a **Bare worker**. On iOS and Android that worker is a **`react-native-bare-kit` Worklet**: a separate Bare JS thread inside the app process. The client talks to it with **`bare-rpc` over `worklet.IPC`**. Native engines are QVAC forks of llama.cpp ("qvac-fabric"), whisper.cpp/speech.cpp, Parakeet-cpp and others, shipped as Bare addons. Prebuild links them into react-native-bare-kit.
- **Fit for Hermit: good feature coverage, with real platform risk.** Each of these is present and code-verified:
  - Tool calling: grammar-constrained, with 7 dialects including Qwen3.5. Parallel calls are on by default since 0.23. Deferred tool search is available.
  - Voice: Whisper + Silero VAD streaming, Parakeet, and Supertonic 3 TTS, which speaks Spanish.
  - Embeddings and RAG: EmbeddingGemma and a TurboVec index.
  - On-device LoRA fine-tuning.
  - Suspend/resume for app lifecycle.

  The weak spots:
  - **Android GPU quality varies a lot by chip.** The SDK forces **all Google Pixel phones to CPU** for LLM and embeddings. QVAC's own benchmarks put Pixel 9 Pro CPU decode at about 1–2 tok/s, and Qwen3.5-2B gave garbled output on the Pixel 9 Pro.
  - **iOS memory ceiling.** About 3.8 GB of model plus mmproj fits on an 8 GB iPhone; anything larger was killed by jetsam.
  - **Build and packaging churn**, covered in Risks.
- **"Delegation" is gone.** Phone-to-provider DHT delegated inference was removed by PR #4042 (merged 2026-08-26, shipped in 0.19.0). Two P2P pieces remain:
  1. Model distribution: the QVAC registry over Hyperswarm/Hypercore, plus Hyperdrive.
  2. A new **ggml RPC "rpc-servers"** feature: layer-split inference across machines, with endpoints discovered on a Hyperswarm topic. It is **unencrypted and unauthenticated**, for trusted LANs only, and the client streams tensors to the servers. It is not a fit for "Boost".
- **Privacy.** No telemetry or analytics SDKs were found. The only network activity is model download. By default that goes through **QVAC's P2P registry over Hyperswarm**, including the `registry://hf/...` constants. Joining the DHT exposes the device IP to DHT peers and Tether-run seeders, and shows which model blob it fetches. Hermit can avoid this by using its own HTTPS URLs, bundled files, or a self-hosted source, and by keeping first download separate from runtime.

## 3. Integration pattern for Hermit

### 3.1 Where inference runs

```
React Native (Hermes, JS thread)                  Bare Worklet (separate thread, same process)
-------------------------------------             ---------------------------------------------
@qvac/sdk client  (expo-rpc-client.ts)            worker.mobile.bundle.js (built at prebuild)
  getRPC() -> new Worklet()                         createBareKitRPCServer(): new RPC(BareKit.IPC,
  worklet.start('worker.bundle', bundle,              handleRequest)   (worker/create-server.ts:9-11)
     ['react-native-bare-kit','worker.js',          @qvac/inference handlers -> native addons
      {HOME_DIR: Paths.document}])                   (llm-llamacpp, embed, whisper/parakeet, tts...)
  new RPC(worklet.IPC)  <== bare-rpc duplex ==>     Hyperswarm/Corestore (only for downloads)
  completion()/transcribeStream()/... streams
```

- **Singletons.** There is one Worklet and one RPC client per app (`expo-rpc-client.ts:13-16,50-124`). The first SDK call starts it lazily. `close()` sends `__shutdown__` and then `worklet.terminate()` (`:140-220`). The ordering prevents an iOS SIGTRAP when the worklet is restarted.
- **Bundle.** The Expo plugin builds `dist/worker.mobile.bundle.js` with bare-pack at `expo prebuild`. It tree-shakes by the `plugins` list in `qvac.config.json` and links native addons into react-native-bare-kit (`withMobileBundle.ts`, `link-addons.ts`). **Run `expo prebuild` again after every `npm install`**; reinstalling wipes the linked addons.
- **Config.** `qvac.config.json` is read once at init (`__init_config`) and is immutable afterwards (`packages/inference/src/schemas/config.ts:100-105`). That makes it the place for `cacheDirectory`, `swarmRelays`, `requireHttpChecksum`/`requireSecureTransport`, `modelFitPolicy` and `deviceDefaults` overrides. Use `deviceDefaults` to re-enable GPU on specific Pixel models once validated.

### 3.2 Recommended Hermit wiring (code-level)

1. **Dependencies.** Pin `@qvac/sdk@0.23.x` exactly, `react-native-bare-kit@~0.16.0` (not 0.17), `bare-rpc`, `expo-file-system`, `expo-build-properties` and `expo-device`. Also pin the matching `@qvac/fabric-ios` and `@qvac/fabric-android-arm64` versions, which `installMissingPrebuilds` will name. Use Expo 54 to match QVAC CI, or 55–57 with your own testing.
2. **app.json.** Add `["@qvac/sdk/expo-plugin", {"installMissingPrebuilds": false}]`, set `newArchEnabled: true`, and set the Android minSdk to 31 to match the template and the documented Android 12+.
3. **qvac.config.json.** Make it minimal and tree-shaken. Use `plugins: [llamacpp-completion, llamacpp-embedding, whispercpp-transcription (or parakeet), tts]`, set `cacheDirectory` to a non-backed-up Application Support/Library path rather than Documents, and set `requireSecureTransport: true` and `requireHttpChecksum: true`.
4. **Model delivery that keeps the privacy promise.** Use explicit `https://` model URLs from Hermit-controlled or HF mirrors with a known sha256, or bundled or side-loaded files, instead of `registry://` constants. Alternatively, keep the constants but tell the user that the first download is P2P. Use `downloadAsset` with progress before `loadModel`.
5. **Agent loop and cage.** Call `completion({modelId, history, tools, generationParams:{tool_choice, parallel_tool_calls}})` and collect `await result.toolCalls`. **Every call returns to the RN side unexecuted** (`tool-helpers.ts:114-128`). Hermit's cage then runs: policy check → vault → biometric approval → signed audit → execute → push `{role:'tool', content}` into the history → next `completion`. Never pass `handler` into `ToolInput`, so `invoke()` cannot bypass the cage. Use `tool_search`/`deferLoading` for large tool sets, and use `kvCache`/`cacheKey` plus the 0.23 `prefill` priming to cut time to first token on long system prompts.
6. **Lifecycle.** Call `suspend()` on AppState background and `resume()` on foreground (`docs/.../runtime/lifecycle.mdx`). On iOS, keep only one LLM loaded at a time, plus the small ASR, TTS and embedding models.
7. **Voice.** Capture native PCM at 16 kHz in f32le, then `transcribeStream({modelId})` with `session.write(chunk)` and `for await (text of session)`. Use Whisper + Silero VAD for Spanish, then `completion`, then `textToSpeechStream` with Supertonic 3 `language:'es'`. Port the gating logic from `examples/voice-assistant/voice-assistant.ts:143-224`.
8. **Boost (phone → user's computer).** Do **not** build Boost on QVAC rpc-servers. They are an unauthenticated plaintext ggml tensor protocol, they need the model weights on the client, and they are LAN-only. Better: run `qvac serve --openai` (OpenAI-compatible `/v1/chat/completions` with streaming and tool calls, `--api-key`) or the SDK on the computer. Then tunnel it over Hermit's own Noise-encrypted, key-pinned Hyperswarm/secret-stream channel. Hyperswarm already ships inside the worklet, either in a second bare-kit worklet or as a custom QVAC plugin (`docs/.../configuration/plugins/write-custom-plugin.mdx`). Note the QVAC docs recommend `qwen3.5-9b` for "real agent work", which is a good Boost target.

## 4. Risks

1. **API churn.** The SDK is 0.x and every minor since 0.19 has carried 3–10 breaking-change sections. Budget an upgrade every ~2 weeks or pin and lag deliberately.
2. **react-native-bare-kit 0.17.** It shipped 2026-11-02 with a different packaging model, and QVAC's peer range `>=0.16.0` would accept it. Expect silent addon-link breakage if it is not pinned.
3. **Android GPU fragmentation.**
   - Pixel/Tensor is forced to CPU, about 1–2 tok/s on the P9P, and output was garbled on GPU.
   - Adreno 830 Vulkan crashes; OpenCL is used instead, but it rejects quantized KV.
   - Mali gets a CPU projector.
   - A "phone-first" promise will be uneven on Android. Pixel users need either a ≤1B model or Boost.
4. **iOS memory.** About 3.8 GB is the practical ceiling on 8 GB iPhones (jetsam), which caps you around the 2B–4B Q4 class. LLM, ASR, TTS and embeddings share one process budget.
5. **Packaging and App Store.**
   - Issue #4913: ITMS-90208, invalid MinimumOSVersion in the addon frameworks, fixed through bare-link 3.3.2.
   - Issue #4630: EAS build failed on 0.20.
   - Issue #4685: prebuild crashed on undocumented native deps.
   - Issue #2444: 3.7 GB node_modules.
   - Issue #4072: a 27 MB ffmpeg addon always linked.
   - Every `npm install` needs a re-prebuild.
6. **Docs lag the code.** The fine-tuning arch list is stale, Android minSdk differs between docs (12) and the plugin (29), the tutorial mentions Expo Go, and the system-resources matrix states "No physical-device acceptance" for iOS and Android.
7. **Privacy metadata.** By default, registry downloads join the public Hyperswarm DHT, using Tether's bootstrap and seeders. This needs either different model delivery or explicit disclosure to honor "tells no one".
8. **Vendor concentration.** A single company (Tether) controls the inference forks (qvac-fabric), the registry key, and the release train. Apache-2.0 makes forking possible, but the native toolchain (vcpkg, fabric, bare-link) is heavy.
9. **Small-model tool reliability.** QVAC's own docs say small models are "less reliable with tool-heavy agent sessions". Phone-class models (0.8B–4B) will need fine-tuned LoRA adapters or strict `tool_choice`/grammar to be dependable.
10. **Fine-tune on device.** Q4_K_M bases cannot be fine-tuned; a Q8_0 or F16 base is required, which means more RAM. On Adreno below 800 fine-tuning is CPU only. Fine-tuning and inference on the same model are exclusive.
11. **Bundled fork performance.** The docs recorded a 37–70% Metal decode regression of the QVAC "fiber" fork vs upstream on the iPhone 16e (May 2026). Current status is unknown, so benchmark the shipped version yourself.

## 5. Open questions (for Hermit to decide or measure)

1. **Model delivery.** Should Hermit use QVAC registry P2P (fast, decentralized, leaks IP and model choice to DHT peers), Hermit-hosted HTTPS with pinned sha256, or HF HTTPS? Does the privacy promise cover "first download"?
2. **Android floor.** Should Pixel/Tensor and Mali devices be supported at launch on CPU with a tiny model (Qwen3-0.6B or Qwen3.5-0.8B), steered toward Boost, or should Hermit initially require Adreno 7xx+ or iPhone 15 Pro+ class hardware?
3. **Default phone model.** Qwen3.5-2B Q4_K_M (1.28 GB, about 28 tok/s on an iPhone 16e upstream) vs Qwen3-1.7B vs Qwen3.5-4B (2.7 GB, about 12 tok/s)? This needs Hermit's own text-only, tool-calling benchmark on the shipped 0.23 fabric, on iPhone 15/16 and on S24/S25 and Pixel 8/9.
4. **iOS increased-memory-limit.** Should Hermit request the `com.apple.developer.kernel.increased-memory-limit` entitlement, and does it change the ~3.8 GB ceiling in practice?
5. **Upgrade policy.** Should Hermit pin 0.23.x and upgrade on a fixed cadence, or track latest? Who owns re-validation of the Expo prebuild after each bump?
6. **Boost transport.** Should it be a second bare-kit worklet running Hermit's Hyperswarm + Noise channel to `qvac serve --openai`, or a custom QVAC worker plugin? Pairing UX and key pinning need design.
7. **On-device fine-tuning scope.** Should Hermit ship LoRA training on phones in V1, which needs a Q8_0 base, makes Adreno below 800 CPU-only, and blocks inference while training? Or should it ship pre-trained tool-calling adapters and train only on Boost?
8. **Expo version.** Should Hermit stay on Expo 54 (QVAC's CI baseline) or move to 55–57 (user-reported working on 57) and own the testing?
