# Open-source browser and computer use: what Hermit's web tasks should copy

Research date: 2026-11-11. Read through `gh api` and `raw.githubusercontent.com` only (no clones). Scope: confirm or improve ADR-018 and FR-WEB-05 to FR-WEB-08 (in-app WebView, pruned accessibility tree with numbered elements, typed `web_*` skills, 15 steps, known task kinds, committing clicks approved).

Marks: **V** = verified in the source at the path given; **U** = from memory or docs, not checked in code.

Skipped after triage: Skyvern, LaVague, Agent-S, UI-TARS-desktop (vision-first or Python/CDP; nothing the above do not cover better for a WebView). UI-TARS and similar 7B VLMs are screenshot models and would contradict "never pixels" (U).

## Small-model evidence

- WebRL (THUDM/WebRL, license not checked): RL fine-tuning took Llama-3.1-8B from **4.8% to 42.4%** and GLM-4-9B from 6.1% to 43% on WebArena-Lite, text (accessibility tree) mode (V arXiv 2411.02337 abstract; README links checkpoints).
- Read the other way: an untuned 8B model completes about 1 web task in 20. Hermit's 1B to 4B on-device models, untuned, should be assumed worse. Open-ended web navigation on the phone is not viable; bounded, pre-shaped flows are the only realistic V1 path. This confirms ADR-018's "known task kinds only" and the Boost handoff.
- Every serious project has converged on the accessibility tree plus integer refs for text models (browser-use, Playwright, Stagehand, Nanobrowser, BrowserGym). ADR-018's choice is confirmed.

## What ports to a React Native WebView

`react-native-webview` gives `injectedJavaScript` and `postMessage`, no CDP. So the tree must be built in page JS, not read from Chrome's AX API. Two proven ways:
1. Playwright's injected `ariaSnapshot.ts` plus `roleUtils.ts` (Apache-2.0) computes roles and accessible names in pure DOM JS. Bundle it as the injected script. Best fidelity.
2. browser-use 0.1.40 `buildDomTree.js` (MIT, ~1,000 lines) for visibility, top-element and interactivity checks, plus BrowserGym's id stamping so refs survive between snapshot and action.

Nanobrowser's `classify.ts` (Apache-2.0) ports almost verbatim; it only needs `FormFacts` (form owner, default button, method/action, search form, money text near the button), which an injected probe can compute.

## What Hermit should take

1. **Confirm the tree, fix its exact format (FR-WEB-05).** One line per node, page order, no indentation (saves tokens for a 1B to 4B model):
   `[7] button "Place order" disabled` / `[12] textbox "Email" = "a@b.co"` / `[15] select "Size" = "M" options: S | M | L | +2` / `## Heading` / plain text lines. Header `[page] <title> | <origin>`. Numbering resets per snapshot; a `*` marks refs new since the last snapshot. Budget about 3,000 characters (Nanobrowser's formula gives ~3,200 for a 4k context); when cut, keep the first 80% and the last 20% and print `... N lines cut`. Mask password, card and OTP field values as `***`. Grammar-constrain `web_click`/`web_type`/`web_select` so the ref must be one of the integers printed this turn.
2. **Each action returns a one-line outcome**, not a fresh full tree: `[ok] click [7] button "Next" -> navigated to /checkout | page changed | no change` (browser-use 1.0). Cheap feedback that small models can use; the next snapshot is taken only when needed.
3. **Make FR-WEB-07 a deterministic classifier, ported from Nanobrowser.** Map `pay` to `spend`, `grant` and sign-in to `credential`, `submit` and `delete` to `remote_write`. Add: Enter in a field counts as submit when HTML implicit submission applies; Enter in a formless text box is a send; a generic "Confirm/Continue" next to a money amount is `spend`; search forms are exempt. Keep the existing rule "unclassifiable click on a page with a form defaults to `remote_write`". Policy: err toward prompting.
4. **Revalidate after approval (new FR).** After the fingerprint, re-resolve the ref and confirm role, name, origin and form action still match what the sheet showed; if not, abort. Approval sheets render a human element description (Playwright's `element` field idea) plus the values being sent.
5. **Add recipes (new FR, call it FR-WEB-09).** When a known task finishes with the user's approval, save it on the phone as a recipe: domain, task kind, ordered steps `{op, target_text, container_hint, position_hint, value:"{var}", expected_outcome}` (workflow-use schema, reimplemented, not copied: AGPL). Replay matches targets by role plus accessible name, not CSS. Replay is deterministic and model-free; on a miss, hand only that step to the model with the current tree, then continue. Committing steps in a recipe are still approved every time. Cache key: origin plus task kind plus a hash of the page's interactive roles and names (Stagehand's idea). This is the strongest lever for small models: the model fills variables and handles drift, it does not plan.
6. **Keep 15 steps, add a failure budget.** Stop after 3 consecutive failed or "no change" actions (browser-use uses 5 for larger models), and add a `web_report_infeasible(reason)` skill (BrowserGym) so the model can end honestly, offering Take over or Boost.
7. **Keep "never pixels" and the Boost handoff.** WebRL's 4.8% untuned 8B baseline is the evidence for RSK-09 and ADR-018. A fine-tuned on-device web model is a V2 research option, not a V1 dependency.
8. **License hygiene.** Port from Playwright (Apache-2.0), Nanobrowser (Apache-2.0), browser-use (MIT); record each in `THIRD_PARTY_NOTICES`. Treat workflow-use (AGPL) as design input only.
