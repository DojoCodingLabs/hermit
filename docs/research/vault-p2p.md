# Hermit: vault, audit log and P2P link with PearPass, Autopass and Holepunch

Research date: 2026-11-08. Repos were shallow-cloned read-only to `(local clone) `. No install or build scripts were run. Paths below are relative to that directory unless they are URLs.

## Summary

- **PearPass is paused, confirmed.** The README warning was added on 2026-08-14 in commit `3b85d49` ("add notice", PR #462, merged as `c6afff8`). It is the last commit in `tetherto/pearpass-app-mobile` and in every `pearpass-*` / `pear-apps-*` repo (all last pushed between 13:31 and 13:43 UTC that day). No public announcement backs it up. Press coverage only describes the launch (Dec 2025).
- **Autopass** (`holepunchto/autopass`, Apache-2.0, v3.4.1) is the vault engine under PearPass. It is small (424-line `index.js`) and wraps Autobase, HyperDB, blind-pairing and blind-peering. It still works, but its last release was 2026-04-08, it has 30 stars, and its main consumer is now paused.
- **Biggest finding.** The QVAC SDK (`@qvac/sdk` 0.23.0) already runs a Bare worklet on Expo (`react-native-bare-kit ^0.16`) and already depends on `corestore`, `hyperdrive` and `hyperswarm`. So the native Holepunch addons (rocksdb-native, sodium-native, udx-native) ship in Hermit anyway. A QVAC **custom plugin** can run our Holepunch code inside the same worklet. That removes most of the "second worklet / bundle size" cost.
- **Second finding.** QVAC used to ship "DHT delegated inference" (`startQVACProvider`, `loadModel({delegate:{providerPublicKey}})`), which is almost exactly what Boost needs. **It was removed in 0.19.0 (2026-09-07)** (`qvac/packages/sdk/CHANGELOG.md` ~L1868, `changelog/0.19.0/breaking.md` L58). We would have to build Boost ourselves.
- **Recommendation in short:**
  - **Vault:** use the platform-native approach now (option b).
  - **Audit log:** build our own hash-chained, Ed25519-signed SQLite log now (b). Keep its format close to Hypercore so it can move to Hypercore later.
  - **Boost:** use the Holepunch transport now (option a, narrowly): `hyperdht` plus `@hyperswarm/secret-stream`, running in the QVAC worklet as a custom plugin, with our own QR + 6-digit confirmation. Add a direct-LAN fallback. Do not use Autopass or PearPass code.

## Vault options

| Option | What it is | Pros | Cons |
|---|---|---|---|
| **V1. Autopass in a Bare worklet** | Copy PearPass's pattern (`pearpass-lib-vault-core/src/worklet/appDeps.js`) | Multi-device sync and invites built in; proven on mobile | Its consumer is paused and its last release was April. Block-level encryption leaves the key in plaintext unless we wire `blindEncryption` to a Keychain-held key. No Secure Enclave or StrongBox binding. Biometric gating would have to be implemented across the RN↔worklet IPC, so **the secret crosses into JS heaps in two runtimes**. Debugging means RocksDB plus Autobase linearization inside a worklet. Sync is not needed for V1 (single phone). |
| **V2. Fork pearpass-lib-vault-core** | Reuse the whole Tether vault worklet | Most features (OTP, imports from Bitwarden/Proton/KeePass) | Paused, not on npm (git deps only), pinned to old bare-kit 0.13 / Expo 53. Brings Tether blind mirrors and swarmconf. Large surface we would own. |
| **V3. Platform-native (recommended)** | Per-secret random DEK in `expo-secure-store` (Keychain `WHEN_UNLOCKED_THIS_DEVICE_ONLY` / Android Keystore, `requireAuthentication: true` for biometric prompt) + metadata/handles in SQLCipher (`op-sqlite` with SQLCipher, or `expo-sqlite` with SQLCipher enabled) | Hardware-backed keys, OS biometric prompt bound to the key, mature, easy to debug, no worklet needed. The model only ever sees `vault://handle/<id>`. Injection happens in native/RN code after `LocalAuthentication` succeeds. | No sync (fine for V1). Backup and migration are ours to design. expo-secure-store has a ~2 KB-per-item limit on some Android versions, so store DEKs there and ciphertext in SQLCipher. |

Note: PearPass itself also uses `expo-secure-store` and `expo-local-authentication` for biometric unlock (`pearpass-app-mobile/package.json`). Even Tether's design leans on platform key storage for the unlock step.

## Audit log options

| Option | What it is | Pros | Cons |
|---|---|---|---|
| **A1. Hypercore (single writer) in the worklet** | One core per device; each action is appended as a block | Real signed merkle log; replicates to the user's computer later, which gives external tamper evidence; mature (v11, LTS storage format) | Needs Corestore/RocksDB inside a worklet; RN can only query it over IPC. The owner can still truncate, so without a second replica it is no stronger than A2. Harder to browse and query for the in-app "activity" UI (we would need Hyperbee/HyperDB views). |
| **A2. Hash-chained Ed25519-signed SQLite (recommended now)** | Each row is `seq, ts, actor, action, payload_hash, prev_hash, sig`, where `sig = Ed25519(sk, H(row‖prev_hash))`. `sk` is in Keychain/Keystore (or an Ed25519 key wrapped by a Keystore AES key; Secure Enclave only does P-256, so either use P-256 ECDSA there or wrap the Ed25519 key). Periodic signed checkpoints. | Simple, queryable, cheap to debug, no worklet. Easy to export and verify with a 50-line verifier. | We own the format. Tamper evidence needs anchoring (checkpoint heads exported to the paired computer, which Boost provides later). |
| A3. A2 now, mirror the heads into a Hypercore later | When Boost lands, append checkpoint hashes (not contents) to a Hypercore replicated to the computer | Combines both, with an easy migration path | Extra work later, but no rewrite |

|---|---|---|---|

## Recommendation

1. **Vault: (b) platform-native now.** Use `expo-secure-store` (biometric-bound, this-device-only) for per-item keys, SQLCipher for ciphertext and metadata, and opaque handles for the model. Inject in the RN/native layer only after `expo-local-authentication`. Do not adopt Autopass or PearPass for V1. Revisit Autopass (or a plain Autobase) only if multi-device vault sync becomes a goal, and even then wrap Autobase's key with `blindEncryption` backed by a Keystore/Keychain key.
2. **Audit log: (b) hash-chained Ed25519-signed SQLite now, then (A3).** Once Boost exists, replicate signed checkpoint heads to the paired computer, optionally as a Hypercore, to get external tamper evidence. Design the row format to be deterministic and content-addressed so it can be appended to a Hypercore unchanged.
3. **Boost: (a) Holepunch transport now, narrowly scoped.** Use `hyperdht` + `@hyperswarm/secret-stream` + `protomux-rpc`, packaged as a **QVAC custom plugin** so the app keeps a single Bare worklet. Build our own QR + SAS 6-digit confirmation. Add a direct-LAN path (LAN IP in the QR; daemon-side `DHT.bootstrapper` or a direct UDX connect) so that "works on home Wi-Fi without internet" becomes true. Market it as "works on your home network; over the internet when both sides can reach each other". Plan for an optional user-run blind relay on the computer side for CGNAT cases. Use the removed QVAC delegation code (pre-0.19 `@qvac/sdk`, e.g. 0.18.x on npm) as reference only, not as a dependency.
4. Phone-to-phone agent messaging later: reuse the P1 transport. Evaluate `blind-pairing` and Autobase at that point.

## Risks

- **Paused dependencies.** All PearPass repos have been paused since 2026-08-14 and are not on npm (git-URL dependencies). Autopass has had no release since 2026-04-08. Mitigation: depend on neither. Use only the core Holepunch libraries, which are very active (hypercore 2026-11-06, hyperdht 2026-11-04, bare-kit 2026-10-30, react-native-bare-kit 0.17.1 2026-11-03).
- **QVAC coupling.** QVAC removed P2P delegation in 0.19 and changes its plugin API across 0.x releases. Boost-as-plugin could break on upgrades. Pin QVAC versions and keep the plugin thin, with protocol logic in a separate package so it can move to its own worklet (P2).
- **One worklet, one blast radius.** An uncaught exception in Bare kills the host app. Install `uncaughtException`/`unhandledRejection` handlers in the plugin.
- **Version skew.** QVAC needs `react-native-bare-kit ^0.16`, PearPass pinned 0.13, and the current release is 0.17.1. Avoid mixing bare-kit or addon copies (symbol binding issue, `bare-kit/README.md` "Addons").
- **Backgrounding.** iOS will kill a worklet that keeps sockets open after suspend. Boost must call `swarm.suspend()`/`resume()` and is foreground-first. Long generations should run in the foreground or be resumable.
- **Offline / CGNAT.** Without the LAN bootstrap/direct path, Boost needs internet for the DHT. Double-randomized NATs need a relay (relays are not "no server in the middle", though blind relays only see ciphertext).
- **Debuggability.** Worklet logs go to the OS log via liblog (`react-native-bare-kit/README.md` "Logging"), not Metro. Budget time for tooling.
- **Hypercore truncation semantics.** A single-device Hypercore is not tamper-proof against its own key holder. Do not overclaim "immutable" in the UI until heads are anchored off-device.
- **Third-party mirrors.** If Autopass is ever adopted, disable PearPass-style default blind mirrors (`defaultBlindMirrors.js`), which would send ciphertext to servers we do not control. That would contradict "100% on-device".
