# Shrink the model's job to win parity

Small on-device agents reach frontier-level results only on a closed menu of skills, and they get there by shrinking what the model is asked to do: code routes, parses time, resolves contacts, renders results and decides when to interrupt, while the model fills free-text slots and settles the ambiguous cases. Hermit already follows that recipe and its blind holdout (95/100 on 2026-11-12; 93/100 in the later published runs) is in the range the literature reports for domain-specialised small models matching GPT-4 on a fixed tool set. The biggest remaining gap is speed, not accuracy, and this synthesis finds a concrete cause in Hermit's own code: the prompt prefix changes on almost every call (route-dependent tool block and menu at the very start, a `Now:` line with the current minute, a different system prompt for replies and for the constrained fallback), and on Qwen3.5's hybrid DeltaNet architecture any change before the end of the cached prefix forces a full re-prefill. At about 200 tok/s, a ~1,800-token prompt costs ~9 s, which explains why the 7 to 11 s median turn barely moved after the KV cache was switched on. The second gap is measurement: none of the six competitors (Atomic, Duet, Dots, Grok Bot, Instinct, Muse) publish accuracy or latency, five of them run frontier models on cloud computers, so parity with them has to be defined as feature coverage plus per-family task success plus blind human preference, measured with a stricter ruler (pass^k, minefields, end-state grading, latency inside the score). The third lever is training: every large jump in the literature (TinyLlama 12.7% to 80.1%, FunctionGemma 58% to 85%, Qwen2.5-1.5B 19.4% to 46.2% on BFCL) came from fine-tuning or RL on the narrow domain, and Hermit's harness is exactly the machine that can generate verified training data for that.

## Every published small-model win is a narrow-domain win

The strongest evidence that a sub-4B model can match a frontier model on assistant tool use comes from closed tool sets. **TinyAgent-1.1B reached 80.06% on a 16-tool Mac assistant task (calendar, mail, SMS, reminders, notes) against 79.08% for GPT-4-turbo**, up from 12.71% for its untuned base, by combining fine-tuning, ToolRAG (retrieving only relevant tools plus examples) and an LLMCompiler planner that emits a plan once and executes it in code ([HF model card](https://huggingface.co/squeeze-ai-lab/TinyAgent-1.1B); [arXiv 2409.00608](https://arxiv.org/abs/2409.00608)). The same model scores only 19.70% overall and 0% multi-turn on general BFCL ([arXiv 2511.22138](https://arxiv.org/html/2511.22138v1)). Google's FunctionGemma 270M went from 58% to 85% on its in-house Mobile Actions set through fine-tuning ([Google blog](https://blog.google/technology/developers/functiongemma/)). Apple's ~3B on-device foundation model ships "guided generation, constrained tool calling, and LoRA adapter fine-tuning" rather than relying on raw capability ([Apple ML](https://machinelearning.apple.com/research/apple-foundation-models-tech-report-2025)). Octopus v2 turns each function into one dedicated token and claims GPT-4-beating accuracy at 95% less context, a vendor claim with no independent replication ([arXiv 2404.01744](https://arxiv.org/abs/2404.01744)).

General multi-turn ability at this size is close to zero, which is why the state machine has to live in code. **Qwen3-0.6B scores 1.38% on BFCL multi-turn, Qwen3-1.7B 16.88%, Qwen3-4B 35.25%** and xLAM-2-3B 55.62% ([arXiv 2511.22138](https://arxiv.org/html/2511.22138v1); the paper's own tables are partly inconsistent). Hermit's clause planner, forced first-step calls, fixed ask-user questions and code-side reply follow-through (`packages/model/src/port.ts`) are the correct response: they convert a multi-turn problem into a sequence of single decisions the model can make.

The decision the model is worst at is not which tool, but whether to call at all. **When2Call measured an answer/call/ask/decline F1 of 32.0 for Qwen2.5-0.5B, 29.9 for 1.5B and 17.9 for Llama-3.2-3B, with tool-hallucination rates of 20% to 52%**, and even GPT-4o hallucinated a tool call 26% of the time ([arXiv 2504.18851](https://arxiv.org/html/2504.18851v1)). Hermit's own decision-model spike fits this exactly: on the 100 cases the phrase router misses, BotPsy as a letter-choice decider scored 23/100 and Intern-Decision-0.8B 41/100, both far below the 95% precision bar (`docs/research/decision-models.md`).

### What parity can and cannot mean

Five of the six competitors are cloud agents on frontier models, each with its own cloud computer. Claude Duet (research preview from Oct 21, 2026, Opus 5.5) sends a morning brief, checks connected accounts every few hours and asks approval before sending, paying, signing or deleting ([Fortune](https://www.fortune.com/2026/10/23/anthropic-joins-meta-and-openais-personal-ai-assistant-race-with-duet/); [iGeeksBlog](https://www.igeeksblog.com/claude-duet-proactive-ai-agent/)). ChatGPT Dots flags urgent mail, runs recurring checks, drafts but does not send without permission, and since Oct 28, 2026 texts users first over iMessage and RCS ([Digital Trends](https://www.digitaltrends.com/computing/openai-now-lets-you-text-your-chatgpt-dot-agent-to-get-things-done/); [MindStudio](https://www.mindstudio.ai/blog/chatgpt-dots-vs-muse-grok)); the model name is unverified. Grok Bot runs always-on agents that follow up dropped threads, learn the user's voice and save a workflow shown once as a routine ([x.ai](https://x.ai/news/introducing-grok-bot)). Instinct is reached by text and phone call, runs a "proprietary core model" trained to text first, and keeps state on a persistent cloud computer ([Vellum](https://www.vellum.ai/blog/official-instinct-breakdown); funding figures conflict across sources). Meta Muse reads and sends email, derives reminders from email, offers adjustable proactive "Ideas", and gates outbound actions through a separate Sentinel agent ([Meta newsroom](https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/); [BuiltIn](https://builtin.com/articles/meta-muse)). **Atomic Agent is the only local llama.cpp peer**: one inference produces one GBNF-constrained JSON array of calls, memory lives outside the prompt in SQLite FTS5, reflection runs after each turn off the reply path, tasks are durable cron/interval/reminder jobs, and an opt-in "Fusion" mode pairs a cloud planner with local workers ([GitHub atomic-agent](https://github.com/AtomicBot-ai/atomic-agent)).

None of these products publish accuracy or latency numbers, so benchmark parity cannot be measured; parity can only be defined by features, by Hermit's own per-family task success, and by blind human preference. The shared 2026 feature set is persistent memory with forget, reminders and recurring tasks, proactive outreach (brief, texting first, dropped-thread nudges), messaging read and reply, calendar, approval gates, and background work.

| Capability | Competitors | Hermit today | Gap |
|---|---|---|---|
| Memory with forget | Muse, Duet, Grok Bot, Atomic | remember, recall, forget | Implicit extraction of "details mentioned once" |
| Reminders | All; Muse derives them from email; Dots and Atomic run recurring jobs | remind, list, cancel by the user's words | Recurring reminders, suggested reminders |
| Proactivity | Duet brief, Dots and Instinct text first, Grok and Instinct chase dropped threads | catch-up summaries on request | Scheduled brief, unanswered-thread nudges |
| Messaging | All, mostly with draft-then-approve | read, reply, injection-safe seal | Approval on send for parity of trust |
| Calendar | Dots, Duet | read, add | Edit, conflicts |
| Web, purchases, multi-bot | Muse, Grok Bot, Dots, Duet | Q20: simple flows in V1, open browsing on Boost in V2 | Out of reach for a 0.8B model alone |
| Privacy | All cloud except Atomic; Muse drew complaints about reading private messages ([eMarketer](https://www.emarketer.com/content/meta-muse-fuels-rise-of-personal-agentic-ai-gaps-adoption-remain)) | Fully on device | Hermit's structural advantage |

## Hermit's latency is a prefix-stability problem, not a compute ceiling

The prefill arithmetic sets the floor. On Snapdragon 8 Elite class CPUs, llama.cpp prefill for ~1B Q4_K_M models is **171 to 173 tok/s (Gemma-3 1B), with decode at 62 to 64 tok/s** ([alpharomercoma benchmark](https://github.com/alpharomercoma/snapdragon-vs-mediatek)), consistent with Hermit's ~200 tok/s. A ~1,800-token prompt therefore costs ~9 s before the first generated token. The measured S26 numbers support this decomposition: the fast route (thinking off) still takes a 7.0 s median, against 11.3 s with full thinking (`docs/research/decision-models.md`), so most of the turn is spent re-reading prompts across the pick and reply calls, and the 256-token thinking budget adds the rest at 21 to 32 tok/s decode. (The repo also records 450 to 500 tok/s prompt speed on a short "hola" test in `packages/model/src/profile.ts`; the ~200 tok/s figure for long prompts should be re-measured with cache statistics logged.)

### Why the KV cache saves almost nothing on Qwen3.5

Qwen3.5-0.8B is a hybrid: **18 of its 24 layers are Gated DeltaNet linear-attention layers holding a single running state, and only 6 are full attention** ([Qwen3.5-0.8B config](https://huggingface.co/Qwen/Qwen3.5-0.8B/raw/main/config.json)). A recurrent state cannot be rewound. llama.cpp handles this with context checkpoints (PR #16382, which "removes the need to re-process the entire context in the majority of cases"), but without a checkpoint at or before the divergence point the server logs "forcing full prompt re-processing due to lack of cache data" even when a long prefix matches ([llama.cpp #16382](https://github.com/ggml-org/llama.cpp/pull/16382); [#26004](https://github.com/ggml-org/llama.cpp/pull/26004)). `--cache-reuse` / KV shifting does not work on these models, and reports of full re-processing on qwen3-next and Qwen 3.6 are open issues ([#18497](https://github.com/ggml-org/llama.cpp/issues/18497); [#22746](https://github.com/ggml-org/llama.cpp/issues/22746)); agent harnesses that edit the request tail force re-prefill every step ([qwen-code #14203](https://github.com/QwenLM/qwen-code/issues/14203)). QVAC's own docs say "the tool block sits near the start of the prompt" and that after a deferred tool load the next turn "re-processes most or all of the prompt"; its release notes claim the addon "trims the previous tool block from the KV cache so rotation is free" ([QVAC text generation](https://docs.qvac.tether.io/ai-capabilities/text-generation.md); [QVAC release notes](https://docs.qvac.tether.io/sdk/release-notes/)). Rotation is free on a pure-attention model; on a hybrid one it is a rollback past the DeltaNet state.

Reading Hermit's code shows the prefix changes in at least four ways, each enough to defeat the cache. First, BotPsy's chat template renders the `# Tools` block **before** the system content (`docs/research/harness-inference.md`, Appendix A), and `port.ts` passes only the router-narrowed `offered` skills as `tools`, so two turns with different routes diverge a few dozen tokens into the prompt. Second, `systemPrompt()` in `packages/model/src/prompt.ts` also lists the narrowed menu and a skill-filtered examples block, so the system text itself is route-dependent. Third, the system prompt ends with `Now:` from `describeNowForModel()`, which includes **the current hour and minute**, so the prefix changes every minute. Fourth, the reply step uses a separate `replyPrompt()` system message and the constrained fallback calls `complete()` with a `jsonSchema` and no `tools`, which renders a template with no tool block at all: both start from token zero. Within a single pick step after a tool result the prefix is append-only, which is likely the only place the cache currently hits.

The fix follows Manus's production rules, "keep prompt prefixes stable, serialize JSON deterministically, mask tools instead of removing them" ([Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)). Pass every skill as `tools` in a fixed order on every call; narrow by grammar or by a short hint appended after the conversation, never by editing the tool block; move the minute-level clock and per-turn context into the tail (for example a one-line note attached to the latest user turn) and keep the daily date table separate; and make the reply and fallback calls append to the same sequence instead of starting new prefixes. With a stable prefix, a checkpoint at its end, and the post-prefix state saved to disk (Q35 already accepts on-disk cache), a turn only prefills its new tokens: a few hundred tokens at ~200 tok/s is ~1 to 2 s instead of ~9 s (inference from the arithmetic above). Checkpoints only survived slot save files after #26004 (merged 2026-10-08), whose test re-processed 31 tokens after restore against 210 without it, so QVAC Fabric's llama.cpp pin decides whether the persistent half of this works ([#26004](https://github.com/ggml-org/llama.cpp/pull/26004)). Per-checkpoint state for Qwen3.5-0.8B is estimated at roughly 19 MB plus conv state (computed from config, unverified), small enough to keep one checkpoint per call type.

### Hardware, quantization and thermal levers are second order

The GPU and NPU help prefill, not decode, at this size. Gemma-3 1B on 8 Elite runs **717 to 723 tok/s prefill on OpenCL against 171 to 173 on CPU, while decode drops from 63 to 42 tok/s** ([alpharomercoma](https://github.com/alpharomercoma/snapdragon-vs-mediatek)). On the 8 Elite Gen 5, NPU prefill plus CPU decode was the fastest pairing for every model from 0.6B to 4B, but the Hexagon backend lacks Q4_K matmul and gated DeltaNet op support is unconfirmed ([GenieX #1666](https://github.com/qualcomm/GenieX/issues/1666); [discussion #21702](https://github.com/ggml-org/llama.cpp/discussions/21702)). Hermit's own S26 measurements already found CPU with 8 threads beating QVAC's OpenCL path (prompt about 160 tok/s on OpenCL) and Vulkan breaking grammar decoding (`docs/build/open-questions.md`, W1 list), and Q4_K repack is already active (`docs/research/device-adaptive-runtime.md`), so the cheap CPU wins are taken. Google's LiteRT-LM shows what a production GPU path reaches on an S26 Ultra (Gemma4-E2B 3,808 tok/s prefill on GPU) but Qwen3.5 hybrid support there is unconfirmed ([LiteRT-LM](https://developers.google.com/edge/litert-lm/overview)).

Two runtime checks are worth doing because they fail silently. Thread affinity (`-C/--cpu-mask`) was a no-op on Android until llama.cpp #26838 (2026-08-10), because the code was guarded by `__gnu_linux__` ([#26838](https://github.com/ggml-org/llama.cpp/pull/26838)); Hermit's device-adaptive runtime sets `cpu-mask`, so the Fabric pin matters. Under thermal throttling on the 8 Elite Gen 5, **CPU decode at 4 threads fell to 2.8% of its unthrottled speed and at 8 threads to 0.5%, while 2 threads kept 37 to 38%** ([GenieX #1666](https://github.com/qualcomm/GenieX/issues/1666)); Hermit's runtime already shrinks thinking first under heat, but a thread step-down is missing.

Speculative decoding is real but secondary for short outputs. Upstream llama.cpp merged MTP (2026-05-16; ~75% acceptance with 3 draft tokens and ">2x" on 27B-class Qwen, with a prefill penalty), EAGLE-3 for Qwen3.5, n-gram drafters, and recurrent-state rollback with a correctness guard added after silent corruption ([#22673](https://github.com/ggml-org/llama.cpp/pull/22673); [#24593](https://github.com/ggml-org/llama.cpp/pull/24593); [#31368](https://github.com/ggml-org/llama.cpp/pull/31368)). Qwen3.5-0.8B ships one MTP layer, but whether BotPsy's GGUF kept it is uncertain, and every published number is on desktop or datacenter hardware. N-gram drafting suits tool arguments copied verbatim from the user, with a small `draft-n-max` because each rejected draft on a hybrid model costs a state rollback ([#18471](https://github.com/ggml-org/llama.cpp/pull/18471); [#19493](https://github.com/ggml-org/llama.cpp/pull/19493)). It becomes worth testing once prefix caching removes the bigger cost and thinking tokens dominate.

## Decide in code, think briefly, constrain late

Constraints help where the output is a classification and hurt where the model must reason. "Let Me Speak Freely?" found format restrictions degrade reasoning while JSON mode improves classification accuracy, and that a two-step NL-then-format approach preserves performance ([arXiv 2408.02442](https://arxiv.org/html/2408.02442v3)); the dottxt rebuttal and an independent replication show the effect depends on model and prompt ([dottxt](https://blog.dottxt.ai/say-what-you-mean.html); [Castillo](https://dylancastillo.co/posts/say-what-you-mean-sometimes.html)). CRANE adds a reasoning prefix to the grammar and reports up to +10 points over both constrained and unconstrained baselines ([arXiv 2502.09061](https://arxiv.org/html/2502.09061v3)). JSONSchemaBench reports constrained decoding up to 50% faster ([arXiv 2501.10868](https://arxiv.org/html/2501.10868v2)). Hermit already does think-then-constrain through native Qwen XML calls and lazy grammars; the open item is that strict schemas do not stop fabricated values the schema accepts ([tianpan.co](https://tianpan.co/blog/2026-04-23-tool-hallucination-rate-probe-suite-agent-eval), secondary), which is why enum constraints on argument values (already used for `conversationId` in reply follow-through) should spread to every closed set.

Thinking helps the smallest quantized models more than any other technique in the test-time literature, and it also overthinks. In a 2026 preprint, **Qwen3-0.6B at Q4_K_M scored 16.8% without thinking and 69.2% with thinking on BFCL v3 non-live, against 62.3% and 76.4% at FP16** ([arXiv 2608.22472](https://arxiv.org/pdf/2608.22472), preprint, non-standard scoring). ThinkBrake showed that small reasoning models reach a correct call and then overwrite it: on Qwen3-4B-Thinking, oracle stopping raised accuracy from 85.8% to 94.2% while cutting 80% to 94% of tokens, and a practical rule (stop when the log-probability margin of `</think>` at a sentence boundary is small) kept accuracy with 15% to 25% fewer tokens ([arXiv 2510.00546](https://arxiv.org/html/2510.00546v1); 4B only, tables internally inconsistent). Hermit's dev-set measurements line up: 256 tokens 82/90, 128 tokens 78/90, off 75/90 (`docs/research/harness-diagnosis.md`). ToolRL found that rewarding longer reasoning cut Qwen2.5-1.5B BFCL from 46.20% to 33.23% ([arXiv 2504.13958](https://arxiv.org/html/2504.13958)). The policy that follows is thinking on for decision-heavy turns, off for argument filling after a forced route (Hermit's `fastRoute`), and an early-stop rule rather than a longer budget.

Sampling more does not rescue hard cases. Self-consistency raises accuracy only when single-sample accuracy exceeds 50% and can lower it otherwise ([SLM-MUX, arXiv 2510.05077](https://arxiv.org/pdf/2510.05077)); on GPQA, majority vote lowered per-problem accuracy for most problems at 7B to 8B ([arXiv 2608.11403](https://arxiv.org/pdf/2608.11403)). Router misses are exactly the p<0.5 regime. Cheaper signals exist: the product of tool-call token probabilities, plus a small learned calibrator, improves expected tool-calling utility and generalizes to new APIs ([MICE, arXiv 2504.20168](https://export.arxiv.org/pdf/2504.20168)), but raw confidence used as a hard stopping rule cut ThinkBrake's accuracy from 89.6 to 82.0, so a confidence gate must be calibrated on Hermit's own cases. QVAC exposes no logprobs today (`docs/research/decision-models.md`), so this needs a patch.

Self-correction without an external signal does not help small models ([ToolCritic, arXiv 2510.17052](https://arxiv.org/html/2510.17052v1)), while structured validation feedback lifted ~3B models' tool selection from 0.615 to 0.802 within 2 to 3 iterations, at a cost in precision ([SAAG](https://www.alphaxiv.org/abs/2607.18245)). For routing, efficient classifiers match LLM routing at far lower latency ([arXiv 2505.14524](https://arxiv.org/pdf/2505.14524)), and a SetFit-then-LLM hybrid came within 2% of a pure LLM at about half the latency ([arXiv 2410.01627](https://arxiv.org/html/2410.01627v1)). Hermit measured raw EmbeddingGemma similarity at only 60% to 86% precision on router misses (Q34), so the untested variant is a trained classifier head on a larger bilingual bank, used only to abstain-or-ask, not to force calls. Dynamic few-shot retrieval is widely recommended for small models, with practitioner reports of large gains at 2 to 3 shots and regressions at 8 (unverified, [tianpan.co](https://tianpan.co/blog/2026-04-12-dynamic-few-shot-retrieval-static-examples-accuracy)); "fewer tools per prompt" has a peer-reviewed edge result of up to 70% less execution time and 40% less power with higher success ([Less-is-More, arXiv 2411.15399](https://arxiv.org/html/2411.15399v1)). On a hybrid model both must be implemented as tail additions or grammar masks, never as prefix edits.

## Train the harness into the weights

Every strong small tool-caller from 2025 used the same data recipe: a frontier teacher generates calls against a fixed API set, rules and execution filter them, a judge filters again, and negatives teach when not to call. APIGen-MT builds verified blueprints and simulates multi-turn interplay; its 1B model reached 43.12% BFCL v3 multi-turn ([arXiv 2504.03601](https://arxiv.org/pdf/2504.03601); xLAM-2 weights are cc-by-nc, so only the method is reusable). ToolACE adds dual-layer verification ([arXiv 2409.00920](https://arxiv.org/html/2409.00920v2)); Hammer masks function names so the model reads descriptions ([arXiv 2410.04587](https://arxiv.org/html/2410.04587v2)); Magnet builds multi-turn sequences from a tool dependency graph and uses near-miss trajectories for preference optimization ([arXiv 2503.07826](https://arxiv.org/pdf/2503.07826)). Hermit's tool set is small, fixed and executable in its trajectory runtime, which is the ideal case: every sample can be replayed and kept only if the final state matches.

On-policy distillation is the most compute-efficient published way to move a student toward a teacher. The student samples, a same-tokenizer teacher scores every token with reverse KL; **the Qwen3 report's 8B student reached 74.4% on AIME'24 with on-policy distillation at 1,800 GPU-hours against 67.6% with RL at 17,920**, and it also repaired catastrophic forgetting after domain training (IF-eval back from 45% to 83%) ([Thinking Machines](https://www.thinkingmachines.ai/blog/on-policy-distillation/)). The teacher must share BotPsy's tokenizer (Qwen3.5-9B or 27B), so a closed frontier model can only provide SFT data. All published on-policy numbers are 8B students on math or chat; none are sub-1B tool calling.

RL with verifiable rewards gives its largest relative gains at the smallest size. **ToolRL took Qwen2.5-1.5B from 19.41% to 46.20% on BFCL v3 with cold-start GRPO, against 40.67% for SFT**, and cold-start GRPO beat SFT-then-GRPO at every size ([arXiv 2504.13958](https://arxiv.org/html/2504.13958)). Tool-N1 reached 84.82 BFCL at 7B with only a binary format-plus-correctness reward ([arXiv 2505.00024](https://arxiv.org/html/2505.00024v1)); the two papers disagree on reward granularity. For ask-versus-act, **reward-aware preference optimization took a 4B model's tool hallucination from 16% to 1.9% and BFCL irrelevance from 41.1% to 77.4%**, while plain SFT on the same data cost 6.2 AST points and negatives-only training made models over-conservative ([When2Call](https://arxiv.org/html/2504.18851v1)). For Spanish, Amazon's "Argument Language Mismatch" study found SFT fixes most wrong-language argument values and argument-aware GRPO adds robustness ([arXiv 2608.11715](https://arxiv.org/pdf/2608.11715)).

The pitfalls are forgetting and template mismatch. Narrow SFT collapsed Qwen2.5-7B's Bamboogle score from 69.6 to about 29 while GRPO kept it at 72.0 ([ToolRL](https://arxiv.org/html/2504.13958)); a 30% chat mix and on-policy distillation from the original model recovered most instruction following ([Thinking Machines](https://www.thinkingmachines.ai/blog/on-policy-distillation/)). FunctionGemma only enters function-calling mode under the `developer` role it was trained on ([Medium GDE](https://medium.com/google-developer-experts/on-device-function-calling-with-functiongemma-39f7407e5d83)), the same lesson Hermit learned when switching to BotPsy's native format gained 4 to 9 points. Gemma 3's QAT cut the Q4_0 perplexity penalty by a reported 54% with about 5,000 distillation-style steps ([Google Developers Blog](https://developers.googleblog.com/en/gemma-3-quantized-aware-trained-state-of-the-art-ai-to-consumer-gpus/), vendor-reported). Training cost is low: Unsloth lists about 3 GB of VRAM for bf16 LoRA on Qwen3.5-0.8B, and GRPO works with `fast_inference=False` ([Unsloth docs](https://unsloth.ai/docs/fr/modeles/qwen3.5/fine-tune)); the Hermit dev Mac cannot train, and teacher inference dominates the budget. BotPsy's derivative-license terms were not found and should be checked before fine-tuning it rather than base Qwen3.5-0.8B.

## Memory and proactivity belong in code and in the background

Memory benchmarks are protocol-dependent and mostly measured with cloud models, so their rankings say little about a 0.8B reader. Mem0's paper ranked itself near Zep on LoCoMo; an independent re-run reversed it (Zep 79.09, Mem0 62.47) ([Mem0 paper](https://arxiv.org/html/2504.19413v1); [Memori](https://arxiv.org/pdf/2603.19935)). The design shifts that hold across systems are all code: **Mem0's 2026 algorithm moved to single-pass ADD-only extraction and fuses semantic, BM25 and entity-match signals** (vendor-reported LoCoMo 92.5) ([Mem0 2026](https://mem0.ai/blog/state-of-ai-agent-memory-2026)); Zep's bi-temporal graph reports up to +18.5% accuracy and 90% lower latency than full context on LongMemEval ([arXiv 2501.13956](https://arxiv.org/abs/2501.13956v1)); Letta moves memory rewriting to a background "sleep-time" agent ([Letta](https://letta.com/blog/sleep-time-compute)). The only small-reader numbers are low: Qwen2.5-3B with SimpleMem reached 17.98 F1 on LoCoMo against 13.03 with Mem0 ([SimpleMem](https://arxiv.org/pdf/2601.02553)). Temporal questions remain the hardest category everywhere, which Hermit's deterministic time parsing already addresses at write time. For retrieval, **EmbeddingGemma-300M scores 61.15 on MMTEB multilingual v2, 60.62 at Q4_0, and supports Matryoshka truncation to 128 dimensions** ([HF card](https://huggingface.co/google/embeddinggemma-300m)); brute-force sqlite-vec plus FTS5 fused by RRF is ample for thousands of personal facts ([sqlite-vec hybrid](https://alexgarcia.xyz/blog/2024/sqlite-vec-hybrid-search/index.html)). No Android latency figures were found, so Hermit must measure its own.

Proactivity is the competitors' headline feature and the hardest one to judge. **GPT-4o reaches about 64.6% F1 on ProactiveBench, and fine-tuned 7B to 8B models about 66%** ([arXiv 2410.12361](https://arxiv.org/html/2410.12361v2)); no result exists below 7B. Shipping on-device systems avoid letting a model decide to interrupt: Pixel Magic Cue runs Gemini Nano over Gmail, Calendar, Messages and Screenshots and shows inline chips rather than notifications ([Google blog](https://blog.google/products-and-platforms/devices/pixel/google-pixel-magic-cue-ai-feature/)), and Samsung Now Brief processes data on device and changes by time of day ([Samsung](https://news.samsung.com/uk/the-first-step-towards-true-ai-companion)). Timing matters more than content: **state-aligned timing raised suggestion acceptance from 0.444 to 0.676** in a 32-person study ([arXiv 2602.00880](https://arxiv.org/html/2602.00880v2)), and users called a constantly suggesting assistant "distracting" and "annoying" ([CHI'25](https://dl.acm.org/doi/10.1145/3706598.3714002)). The recipe for Hermit is deterministic triggers (morning brief, event soon, reminder due, an incoming question answerable from stored facts, a thread left unanswered), a rate cap and per-trigger acceptance learning in code, and the 0.8B model only phrasing the result.

## Measure parity with a stricter ruler

Aggregate accuracy hides the failures that matter at 0.8B. **pass^k (success on all k runs) turns a 90% pass^1 model into about 43% at k=8** with independent failures ([aiwiki tau2](https://www.aiwiki.ai/wiki/tau2-bench), secondary), and Anthropic recommends pass^k whenever every interaction must work ([Anthropic](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)). ToolSandbox's 224 "insufficient information" scenarios, where any tool call is a violation, are hard even for frontier models ([arXiv 2408.04682](https://arxiv.org/pdf/2408.04682)). Quantization to Q4_K_M dropped xLAM-2-3B multi-turn BFCL from 58.00% to 51.75% and increasingly produced "error-free but wrong trajectories" that runtime errors never surface ([NeurIPS 2026](https://neurips.cc/virtual/2026/171271)). tau2's dual control, where the user also acts, cut GPT-4.1 by 18 points ([emergentmind](https://www.emergentmind.com/topics/2-bench), secondary). Hamel Husain's guidance (binary labels, judges validated as classifiers on 100 to 200 labels per failure mode, human error analysis first) fits Hermit's lab ([AI Evals FAQ](https://hamel.dev/blog/posts/evals-faq/)). Auto-tuned harnesses overfit their tuning set ([O'Reilly](https://www.oreilly.com/radar/?p=20067), secondary), and every phrase-router entry added after reading failures is a degree of freedom fitted to the eval; Hermit's trajectory eval already runs pass^4, but blind holdout 2 has only been run at seed 7.

## First-principles thinking: what a turn is made of

A turn's latency is the sum over model calls of (new prompt tokens divided by prefill rate) plus (generated tokens divided by decode rate). At ~200 tok/s prefill and 21 to 32 tok/s decode, a turn with two calls that each re-read 1,500 tokens spends ~15 s on prefill alone, and a 256-token think block adds 8 to 12 s. The levers, in order of size, are therefore: make each call's new-token count small (stable prefix, append-only history, one sequence per call type), make the number of calls per turn small (render tool results from templates, answer from the pick when possible, which Hermit already does), and only then make tokens faster (threads, quant, speculation). A 10x on the first lever beats a 2x on the last.

A turn's accuracy is the product of the probabilities of each decision being right. Each decision moved into code with ~100% reliability (time parsing, contact resolution, conversation ids by grammar, routing when the phrase router is sure) removes a factor from that product. The model's irreducible job is free-text slot content (a reminder title, a fact, a reply body) and the ambiguous call/ask/decline decision on unrouted phrasings. That residue is exactly what When2Call shows small models are worst at, and exactly what preference training fixes. Everything else is harness.

Parity, from first principles, is a user perceiving equal or better outcomes at acceptable latency. Competitors cannot be benchmarked, so parity must be measured on Hermit's side: the same scripted tasks run against Hermit and a competitor, rated blind by people who experience the real latency. The privacy family is the one where Hermit wins by construction (Q31 already encodes this).

## Contrarian thinking: where the consensus could be wrong for Hermit

"Fewer tools in the prompt is always better" is wrong for Hermit as implemented. Less-is-More and TinyAgent's ToolRAG cut tokens on pure-attention models; on a hybrid model with the tool block at the start, a per-route tool list makes every route change a full re-prefill. Manus's rule, mask tools rather than remove them, is the correct reading ([Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)). The token saving is real only if the narrowed list is enforced by grammar after a static block.

"The bitter lesson will wash the harness away" is right at frontier scale and wrong at 0.8B in the near term. Practitioners report deleting most tools and getting better agents ([Phil Schmid](https://www.philschmid.de/agent-harness-2026), secondary), but the part of the harness tied to the device (time zones, OS APIs, permissions, contacts) never moves into weights, and the linguistic part can be distilled deliberately ([Arize](https://arize.com/blog/agent-harness-distillation/)). The synthesis: keep the harness, make every rule pay rent by logging its hits, and run an "ablate the harness" eval after each fine-tune to delete the rules the model has absorbed.

"Thinking hurts small models" is contradicted by the quantized-0.6B data (16.8% to 69.2% with thinking) and Hermit's own 82 vs 75 on the dev set, yet supported by ThinkBrake's overwrite effect. The contrarian position that holds is narrower: thinking helps the decision and hurts once the decision is made, so the right control is an early stop, not a bigger or smaller budget.

"A second small model will fix routing" is contradicted by Hermit's own spike (23 to 41/100 on router misses) and by the p<0.5 voting argument. "Escalate the hard 5% to the cloud" has strong evidence (Hybrid LLM sent 22% of queries to the large model with under 1% quality loss, [arXiv 2404.14618](https://arxiv.org/pdf/2404.14618.pdf)) and Atomic ships it as opt-in Fusion, but it conflicts with Hermit's privacy position; it is a product decision, and the first step is measuring what fraction of organic requests fail on device. "Multi-agent beats single-agent" does not apply at this size: shared context and fewer hops are favored ([Cognition](https://cognition.ai/blog/dont-build-multi-agents)).

## Paradoxical thinking: tensions that point to the answer

The KV cache is on and saves almost nothing. The narrowing that was meant to save prompt tokens costs the whole prompt every time the route changes, and the minute-level clock that fixed time arithmetic invalidates the cache every minute. Resolving the paradox means separating what is constant (tool block, instructions) from what is variable (clock, route hint, memory, examples) by position, not by content.

Making the model do less makes the product look smarter. Fewer tools raised success ([Less-is-More](https://arxiv.org/html/2411.15399v1)), stopping thinking early raised accuracy ([ThinkBrake](https://arxiv.org/html/2510.00546v1)), and the only proposed fix for an 800M model that never finished an email round trip was to render the tool result directly instead of feeding it back ([iunera](https://www.iunera.com/kraken/projects/why-an-800m-model-cant-send-an-email-the-context-confusion-problem/), single practitioner). Hermit's template-rendered confirmations are this paradox put to work.

The smallest model benefits most from both thinking and training. Quantization hurts non-thinking 0.6B the most, and RL gains are largest at the smallest size tested; the cheapest model to run is the one where spending on reasoning tokens and training returns the most.

Evaluating harder lowers the score and raises quality. Moving the headline from pass^1 to pass^4 with minefields and a latency budget will drop the 95/100, and that drop is the point: it exposes silent wrong trajectories and variance users feel. Training to refuse makes the assistant more useful, but only when balanced; negatives-only training makes it timid (When2Call). Proactivity is the competitors' strongest feature and the easiest way to annoy users; the winning version interrupts less and more precisely. Finally, Hermit's weakness (a tiny model on a phone) is the root of its only uncopyable advantage (nothing leaves the device), while every cloud competitor is one privacy incident from Muse's reputation problem.

## Conclusion

The research reframes Hermit's next phase. Accuracy parity on the VA menu is close to the literature's ceiling for a harnessed small model, and further harness rules risk fitting the eval rather than users. The large wins left are structural: a byte-stable prefix that lets the existing KV cache work on a hybrid model (the single biggest latency lever, and one visible in Hermit's own `port.ts` and `prompt.ts`), a training run that converts the harness's verified outputs into weights with preference data for call/ask/decline, and an eval that measures what parity actually means for users (reliability across runs, refusal on minefields, latency inside the score, blind preference against named competitors). Proactivity and memory, the features competitors market hardest, are best built as code-driven background systems with the 0.8B model reduced to phrasing.

The uncomfortable implication is that some parity items cannot be reached by any trick at 0.8B on device: open-ended web tasks, purchases, multi-bot orchestration. Hermit can match the competitors on the personal-assistant core and beat them on privacy, and the decision on whether to offer an opt-in cloud path for the rest is a product choice, not a research gap.

## Prioritized tips, tricks and hacks for the Hermit repo

Priority 0 items attack the measured bottleneck or protect the integrity of the numbers. Priority 1 items are cheap test-time and runtime changes. Priority 2 items need training or new subsystems. Priority 3 items are experiments or product decisions.

### Priority 0: make the cache work

1. **Pass every skill as `tools`, in a fixed order, on every call.** Narrow with a grammar on the `<function=` name or with a hint appended after the history, never by changing the `tools` array. Evidence: Manus "mask, don't remove"; hybrid models re-prefill on any prefix change ([#16382](https://github.com/ggml-org/llama.cpp/pull/16382)). Hermit today: `port.ts` sends only `offered` (route-narrowed) skills, and the template renders tools before the system text.
2. **Make the system prompt route-independent.** Render the full menu and a fixed examples block once instead of `skills.map(...)` and the skill-filtered `EXAMPLES` in `systemPrompt()`. Evidence: same as above. Hermit today: the menu and examples depend on the route.
3. **Move the minute-level clock out of the prefix.** Keep the daily date table in a stable spot (it changes once a day) and put `HH:MM` in a short note attached to the latest user turn. Evidence: append-only rule ([7minai guide](https://7minai.com/llama-server-context-checkpoints-hybrid-swa-models/), paywalled snippet). Hermit today: `describeNowForModel()` includes the current hour and minute at the end of the system prompt.
4. **Move profile facts behind the conversation, or freeze them per session.** Rebuild them only at session boundaries and accept one re-prefill there. Hermit today: up to 1,400 characters of facts sit in the system prompt (`MAX_PROFILE_CHARS`).
5. **Make the reply step append to the pick sequence.** Add the reply instruction as the last message of the same history, or give replies their own slot with a permanently stable prefix. Hermit today: `replyPrompt()` starts a new prefix every turn.
6. **Make the constrained fallback keep the tool block.** Re-issue the call with the same `tools` and a grammar on the call, rather than `jsonSchema` with no tools. Hermit today: the forced fallback in `port.ts` renders a prompt with no tool block, so it starts from token zero.
7. **Turn off QVAC tool rotation, deferred tools and dynamic compaction on the hot path.** Evidence: QVAC docs say a deferred load re-processes most of the prompt ([QVAC](https://docs.qvac.tether.io/ai-capabilities/text-generation.md)).
8. **Add a CI test that hashes the rendered prefix** (template output up to the first user turn) across routes, languages and minutes, and fails if it changes. Serialize tool JSON with a fixed key order. Evidence: Manus; evals note recommendation.
9. **Log cache hits per call.** Record `cacheTokens` from `final.stats`, prompt tokens processed, and any "forcing full prompt re-processing" log line, and make the KV hit rate a headline speed metric next to the median turn. Evidence: Manus calls it the key production metric.
10. **Check QVAC Fabric's llama.cpp pin for the hybrid-cache fixes:** ctx checkpoints (#16382), checkpoints in save files (#26004), short-prompt eviction (#28302) and reference-counted checkpoints (#30137). Patch or ask Tether if any are missing.
11. **Force a checkpoint exactly at the end of the static prefix** by prefilling it in its own call (checkpoints land after processed prompts or at ubatch boundaries). Evidence: inference from llama.cpp checkpoint behavior.
12. **Prewarm the prefix when the chat opens,** or restore a saved post-prefix state keyed by prompt version and model sha (Q35 already accepts on-disk cache). Then the user's typing time hides any cold start.
13. **Check that thread affinity actually applies.** Confirm the Fabric pin includes #26838, otherwise `cpu-mask` from the device-adaptive runtime is silently ignored on Android ([#26838](https://github.com/ggml-org/llama.cpp/pull/26838)).

### Priority 0: keep the numbers honest

14. **Run blind holdout 2 at four or more seeds and report pass^k and the pass^1 minus pass^k gap.** Hermit today: trajectories run pass^4, blind 2 only seed 7 (`harness-diagnosis.md`, still open). Evidence: [Anthropic](https://www.anthropic.com/research/demystifying-evals-for-ai-agents).
15. **Freeze a fresh blind set written by someone (or a model family) that has not seen the router table,** and retire blind 2 to development status once any of its failures are read. Track "harness rules added per holdout point". Evidence: auto-tuned harnesses overfit ([O'Reilly](https://www.oreilly.com/radar/?p=20067), secondary).
16. **Add a minefield slice** (missing information, out-of-scope requests, injected instructions) where any tool call fails, and report the tool-hallucination rate separately. Evidence: [ToolSandbox](https://arxiv.org/pdf/2408.04682), [When2Call](https://arxiv.org/html/2504.18851v1).
17. **Grade every set by end-state diff** (reminders DB, calendar, notes, sent messages), not only call matching, so silent wrong trajectories show up. Hermit today: only the trajectory eval does this. Evidence: [NeurIPS 2026 quantization study](https://neurips.cc/virtual/2026/171271).
18. **Put latency in the pass criterion:** pass^k at P90 latency under a bar on the S26, with TTFT, time-to-action and thermal state logged per turn, and cooldown gaps in sustained runs. Evidence: [GenieX #1666](https://github.com/qualcomm/GenieX/issues/1666) thermal collapse.
19. **Add language drift (reply language differs from the user's) and argument-language mismatch as first-class metrics.** Evidence: [arXiv 2608.11715](https://arxiv.org/pdf/2608.11715).

### Priority 1: cheap decoding and test-time wins

20. **ThinkBrake-style early stop.** At each sentence boundary in the think block, inject `</think>` when its log-probability margin against the top token is small; or stop as soon as a complete valid tool call has been reasoned to. Needs logits from QVAC. Evidence: [ThinkBrake](https://arxiv.org/html/2510.00546v1) (4B only). Hermit today: fixed 256-token budget.
21. **Thinking by decision type, not by profile.** Keep it on for unrouted turns and for recall-versus-decline and ask-versus-act; keep it off for argument filling after a forced route (`fastRoute`). Evidence: 0.6B Q4 data ([arXiv 2608.22472](https://arxiv.org/pdf/2608.22472), preprint); Hermit dev set 82/78/75.
22. **Expose logprobs from QVAC (patch or upstream request)** and gate acting on the tool-name or first-decision-token probability, calibrated on Hermit's cases; below the threshold, use the fixed ask question. Evidence: [MICE](https://export.arxiv.org/pdf/2504.20168); raw-confidence hard rules can hurt ([ThinkBrake](https://arxiv.org/html/2510.00546v1)).
23. **Score candidates instead of sampling them.** Use the teacher-forced logprob of each shortlisted tool name after the same cached prefix rather than N samples. Evidence: [SLM-MUX p>0.5 argument](https://arxiv.org/pdf/2510.05077).
24. **Do not add self-consistency or a second voting model on router misses.** Hermit's spike (23 and 41/100) is the p<0.5 regime where voting hurts.
25. **Spread enum constraints to every closed argument set:** reminder ids for cancel, known contacts for messaging, weekdays, durations, calendar ids. Hermit today: done for `conversationId` in reply follow-through. Evidence: schema-valid fabrication remains the residual risk ([tianpan.co](https://tianpan.co/blog/2026-04-23-tool-hallucination-rate-probe-suite-agent-eval), secondary).
26. **One structured repair turn quoting the exact validator error, capped at one,** for argument and schema failures only, never for decision errors. Watch precision. Evidence: [SAAG](https://www.alphaxiv.org/abs/2607.18245); [ToolCritic](https://arxiv.org/html/2510.17052v1).
27. **Retrieve 2 to 3 nearest exemplars from `EXAMPLE_BANK`** for unrouted turns and append them after the history (not in the system prompt). Keep k small. Evidence: TinyAgent ToolRAG retrieves examples, not only tools; regressions reported at 8 shots (unverified).
28. **Compress the static tool block** (short parameter names, one-line descriptions, signature style) once it is static, and A/B it on the blind set. Evidence: schema compression saved 44% to 50% of schema tokens ([TSCG, arXiv 2605.04107](https://arxiv.org/pdf/2605.04107), snippet only).
29. **Keep rendering tool results from templates, and call the model again only when synthesis is needed** (catch-up summaries). Evidence: [iunera](https://www.iunera.com/kraken/projects/why-an-800m-model-cant-send-an-email-the-context-confusion-problem/).
30. **Start the tool as soon as the call closes, and show intent from the router instantly.** Parse `rawDelta` events for the function name, and execute without waiting for `completionDone`. Evidence: [QVAC events](https://docs.qvac.tether.io/ai-capabilities/text-generation.md); perceived-speed effects are unproven, so A/B them.
31. **A/B a plain instruction format against native XML on router misses only.** The IFFC preprint reports gains for small models, but native format gained Hermit 4 to 9 points, so treat it as a test, not a change. Evidence: [arXiv 2608.22472](https://arxiv.org/pdf/2608.22472).

### Priority 1: runtime

32. **Step threads down to 2 prime cores when thermal headroom drops,** in addition to shrinking thinking. Threads need a reload (about 2 s on the S26), so do it at a safe point. Evidence: [GenieX #1666](https://github.com/qualcomm/GenieX/issues/1666).
33. **Test n-gram speculative decoding with `draft-n-max` 4 to 8** after the cache fix, for arguments copied from the user. Evidence: [#18471](https://github.com/ggml-org/llama.cpp/pull/18471); rollback cost on hybrids ([#19493](https://github.com/ggml-org/llama.cpp/pull/19493)).
34. **Check whether BotPsy's GGUF kept the MTP (nextn) tensors.** If yes, A/B `draft-mtp` on the phone, watching the prefill penalty. Evidence: [#22673](https://github.com/ggml-org/llama.cpp/pull/22673); Qwen3.5-0.8B config has one MTP layer.
35. **A/B Q8_0 against Q4_K_M on the blind set with McNemar,** and try a mix that keeps the tied 248k-vocab embedding/output head at Q6_K or Q8_0. Evidence: quantization devastates non-thinking 0.6B ([arXiv 2608.22472](https://arxiv.org/pdf/2608.22472)); silent wrong trajectories ([NeurIPS 2026](https://neurips.cc/virtual/2026/171271)).
36. **Confirm QVAC computes logits only for the last prompt token during prefill;** with a 248k vocabulary, all-token logits would be a large waste. Evidence: inference from the config.
37. **Track the Hexagon backend for prefill-only offload,** gated on Q4_0 weights and gated DeltaNet op support. Evidence: [GenieX #1666](https://github.com/qualcomm/GenieX/issues/1666); [#21702](https://github.com/ggml-org/llama.cpp/discussions/21702). Not worth doing until both are confirmed.

### Priority 2: training (PDR-009)

38. **Distill the harness.** Run a frontier teacher inside Hermit's exact harness and template, and record post-normalizer canonical calls as SFT targets; keep normalizers at runtime as validators and count their corrections. Evidence: [Arize](https://arize.com/blog/agent-harness-distillation/); TinyAgent and FunctionGemma jumps.
39. **Build data from verified blueprints.** Write intent, ES-LatAm or EN utterance, gold call sequence and final state, replay each in the trajectory simulator, and keep only state matches. Vary country slang, voseo, 12h/24h time and code-switching. Evidence: [APIGen-MT](https://arxiv.org/pdf/2504.03601); [ToolACE](https://arxiv.org/html/2409.00920v2).
40. **Make 20% to 30% of samples negatives** (missing slot, no fitting tool, ambiguous, chit-chat), balanced, never negatives-only. Evidence: [When2Call](https://arxiv.org/html/2504.18851v1).
41. **Run preference optimization (RPO or DPO) on call/ask/decline pairs,** with near-miss trajectories as rejected samples. Evidence: tool hallucination 16% to 1.9% at 4B ([When2Call](https://arxiv.org/html/2504.18851v1)); [Magnet](https://arxiv.org/pdf/2503.07826).
42. **Keep argument keys and enums in English and values in the user's language,** and generate Spanish natively rather than by translation. Evidence: [arXiv 2608.11715](https://arxiv.org/pdf/2608.11715); [arXiv 2604.13286](https://arxiv.org/pdf/2604.13286).
43. **Use a gated verifiable GRPO reward:** parse, then decision class (acting when it should ask penalized more than over-asking), then simulator end state, then language consistency, plus a length penalty on thinking. Try cold-start GRPO against SFT-then-GRPO. Evidence: [ToolRL](https://arxiv.org/html/2504.13958); [Tool-N1](https://arxiv.org/html/2505.00024v1).
44. **Run on-policy distillation from a same-tokenizer Qwen3.5-9B or 27B teacher,** with ES and EN general chat prompts mixed in to undo forgetting. Evidence: [Thinking Machines](https://www.thinkingmachines.ai/blog/on-policy-distillation/).
45. **Train with the exact static tool block and template the runtime will use,** so the runtime prompt can later shrink to a short index. Evidence: FunctionGemma role lesson; Hermit's own native-format gain.
46. **Keep 20% to 40% general chat in the mix, and track IF-style and chat probes next to the 430 cases.** Evidence: Qwen3-8B IF-eval 85% to 45% after narrow training ([Thinking Machines](https://www.thinkingmachines.ai/blog/on-policy-distillation/)).
47. **Preserve and co-train the MTP head** during fine-tuning so speculative decoding stays possible.
48. **Finish with a QAT-like stage:** the bf16 fine-tune teaches a fake-quantized Q4 student. Evidence: Gemma 3 QAT, about 5,000 steps (vendor-reported).
49. **Ship one merged GGUF, not per-skill LoRAs;** consider activated LoRA only for rare post-turn intrinsics, so the cache is reused. Evidence: [aLoRA](https://arxiv.org/html/2504.12397v5); llama.cpp adapter concurrency limits ([EdgeLoRA](https://arxiv.org/html/2507.01438v1)).
50. **Verify BotPsy's derivative-license terms** before choosing BotPsy over base Qwen3.5-0.8B as the fine-tune base.

### Priority 2: memory

51. **Store facts append-only with `valid_from` and `invalid_at`,** and use deterministic contradiction rules (same subject and slot invalidates the older fact) instead of model UPDATE/DELETE. Evidence: Mem0 2026 ADD-only; Zep bi-temporal edges.
52. **Retrieve with FTS5 BM25, EmbeddingGemma vectors at 128 or 256 dimensions and an entity-name boost, fused by RRF,** entirely in code, with the top 3 to 5 facts appended to the tail. Evidence: [Mem0 2026](https://mem0.ai/blog/state-of-ai-agent-memory-2026); [sqlite-vec](https://alexgarcia.xyz/blog/2024/sqlite-vec-hybrid-search/index.html).
53. **Extract implicit facts in a background job while charging or idle** (Letta sleep-time, Atomic post-turn reflection). Tag provenance (user-said, assistant-said, from a message), and never promote message-derived facts without user confirmation, in line with the untrusted seal.
54. **Cap a profile card at roughly 150 to 300 tokens,** rebuilt in the background from a SQL heat score (frequency, recency, length). Evidence: [MemoryOS](https://arxiv.org/html/2506.06326v1).
55. **Normalize every time expression to absolute dates at write time and keep event time separate from ingest time,** since temporal questions are the weakest memory category everywhere.

### Priority 2: proactivity

56. **Build a deterministic trigger layer:** a morning brief at a learned time, an event in N minutes, a reminder due, an incoming question answerable from stored facts (the Magic Cue pattern), and a thread left unanswered (the Grok Bot and Instinct pattern).
57. **Never let the 0.8B model decide whether to interrupt;** it only phrases the candidate. Evidence: GPT-4o about 65% F1 on [ProactiveBench](https://arxiv.org/html/2410.12361v2).
58. **Add anti-annoyance controls in code:** a daily proposal cap, passive surfaces first (brief card, inline chip), per-trigger acceptance learning that suppresses dismissed triggers, and interruptibility gates. Track proposal rate and acceptance. Evidence: [timing study](https://arxiv.org/html/2602.00880v2); [PARE](https://arxiv.org/html/2604.00842v1).
59. **Add recurring reminders and suggested reminders from messages and email** to match Dots, Atomic and Muse.
60. **Make outbound messages draft-then-approve by default,** matching every competitor's approval gate.

### Priority 3: experiments and product decisions

61. **Plan once, execute in code, for multi-intent messages:** one constrained generation emits the ordered call list (Atomic, LLMCompiler) instead of one pick per clause. Compare it with the clause planner on the blind set. Evidence: [atomic-agent](https://github.com/AtomicBot-ai/atomic-agent); [TinyAgent](https://arxiv.org/html/2409.00608v3).
62. **Use single-token canonical tool names** (a cheap variant of Octopus functional tokens) so a grammar can decide the tool in one step. Evidence: [Octopus v2](https://arxiv.org/abs/2404.01744), vendor-reported.
63. **Revisit the learned router as a trained classifier head on a larger bilingual bank,** used only to abstain or ask on phrase-router misses, never to force. Evidence: [SetFit hybrid](https://arxiv.org/html/2410.01627v1). Hermit today: raw EmbeddingGemma similarity reached 60% to 86% precision on misses (Q34).
64. **Add a dual-control trajectory family** (the user must grant a permission or change a setting mid-task). Evidence: tau2 drop of 18 to 25 points.
65. **Run an "ablate the harness" eval at every model upgrade:** model alone against model plus each harness layer, per family, so rules the model has absorbed can be deleted. Log rule hit counts on organic traffic (Q32 opt-in).
66. **Run a blind side-by-side human preference study against named competitors** on the same scripts with real-latency recordings, scored win/tie/loss with reason tags, as the Q31 parity gate.
67. **Measure how often organic requests fail on device, then decide on an opt-in cloud path for the hard few percent** (Atomic Fusion style, explicit privacy UI). This is a product decision, to be logged in `docs/build/open-questions.md` before it is asked. Evidence: [Hybrid LLM](https://arxiv.org/pdf/2404.14618.pdf); [token-level routing](https://arxiv.org/html/2504.07878v1).

Extra tips from the cross-check:

68. **Refer by id, never by retyped text.** Where the model must name an existing item (a reminder to cancel, a fact to forget, a message to reply to), offer short ids in the tool result and grammar-pin the argument to those ids, as `conversationId` already is for replies. Extend it to `reminder_cancel.which` and `forget`.
